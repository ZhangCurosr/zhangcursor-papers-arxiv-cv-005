# 论文速读：VideoMemBench: How Well Do MLLMs Remember in Video Conversations?

## 一句话总结
提出 **VideoMemBench**，首个专门评估多模态大语言模型（MLLMs）在单视频长对话中**上下文视频记忆**能力的基准测试，通过显式构建带有**情节依赖**与**答案依赖**的跨轮次对话链，发现当前最强模型（Claude Opus 5）在此任务上的整体得分仅 45.7%。

## 研究问题与动机
- **核心问题**：当 MLLM 处理单视频长对话时，能否正确检索并复用对话早期已确立的信息（包括视觉内容与自身先前回答）？作者将此能力定义为 **in-context video memory**。
- **现有基准测试的缺陷**：现有视频 QA 基准测试（如 MVBench, Video-MME, LongVideoBench）中的问题是**相互独立**的，每个问题均可仅凭视频本身回答，无需携带对话历史信息，因此无法测量跨轮次记忆能力。
- **评估挑战**：需将真正依赖对话历史的问题与仅凭视频即可回答的问题区分开来，并保证依赖的**必要性**（移除父节点后问题不可答）和**非泄漏性**（当前问题不重述父节点信息）。
- **动机**：随着 MLLM 能处理长达数小时的视频，基于单个视频的扩展多轮对话成为自然交互模式，亟需相应的评测基准。

## 核心贡献（创新点）
1. **提出 in-context video memory 概念并形式化定义**：将视频对话中的记忆能力分解为对“所见”（视觉情节）和对“所言”（自身答案）的记忆，区别于文本 LLM 的记忆评测。
2. **构建 VideoMemBench 基准测试**：设计了包含 326 个视频、2476 个对话轮次的数据集，其中 1387 个轮次具有显式依赖关系，支持**多父节点**和**长距离**（最长跨 9 个轮次）依赖。
3. **设计带 typed dependency graph 的自动化构建与验证流程**：通过 Planner-Generator-Judger 三角色 LLM 协作，并经过人类专家审查，强制验证依赖的必要性（Necessity）、非泄漏性（Non-leakage）和视觉锚定性（Visual grounding）。
4. **提供系统性评测与分析**：评测了 25 个 MLLM，揭示了依赖距离、父节点数量、对话位置及答案历史正确性对记忆性能的影响规律。

## 方法详解
### 1. 依赖类型设计
- **Episodic Dependency（情节依赖）**：当前问题依赖于**更早轮次所描述的视觉情节**，测试模型对“所见”的记忆。例如，“T₁ 描述的那个场景中有没有河马警官？”模型需回忆 T₁ 的定位信息才能找到对应视频片段。
- **Answer Dependency（答案依赖）**：当前问题建立在**模型自身更早轮次的回答**之上，测试模型对“所言”的记忆与一致性。例如，T₁ 确定嫌疑动物是食蚁兽，T₃ 问“在 T₁ 中确定的目标动物是否会出现在某场景？”，必须沿用 T₁ 的答案。
- **复杂依赖**：支持一个轮次有多个父节点（Multi-parent），以及依赖链条（如 T₁ → T₃ → T₄ → T₇，深度为 3）。

### 2. 有效性约束
- **Req-1 必要性 (Necessity)**：移除父节点后，问题必须无法仅凭视频和剩余对话回答。
- **Req-2 非泄漏性 (Non-leakage)**：当前问题不得部分或全部重述父节点的剧情描述或答案。
- **Req-3 视觉锚定性 (Visual grounding)**：每个轮次的回答都必须能在视频帧中找到可验证的视觉证据。

### 3. 自动化构建流程（三 LLM 角色）
- **Planner（规划者）**：在生成任何问题前，先制定全局对话计划，包括视频摘要、依赖图、每轮意图（intent）和证据窗口（evidence window）。
- **Generator（生成器）**：按计划在轮次上逐步生成问答。对于依赖轮次，仅使用指代表达式（如 "the player identified in T₁"）引用父节点，不重述信息。
- **Judger（验证者）**：对每个生成的轮次进行三项检查：
    - **必要性探测**：模拟移除父节点，用 LLM-as-a-Judge 验证问题是否因此变得不可答。
    - **泄漏检查**：对比当前问题与父节点问题/答案，检查是否存在信息泄露。
    - **视觉锚定检查**：仅查看标注的证据窗口帧，验证答案是否可由帧内容支持。
- **失败轮次**会被反馈给 Generator 重新生成，连续两次失败则触发局部重新规划。
- **人工专家审查**：所有通过自动检查的对话由 8 位人类专家复核。

### 4. 评估协议
- **输入**：所有模型接收固定采样的 **128 帧**（带时间戳），视频帧在整个对话中持续可用。
- **对话历史**：严格按顺序呈现问题，模型自身的先前回答被保留在历史记录中（self-rollout）。
- **公式化评估指标**：
    - **TurnAcc**：所有轮次的独立准确率。
    - **EpiDepAcc**：仅评估有情节依赖的轮次，独立计分。
    - **AnsDepAcc**：评估有答案依赖的轮次，采用**链式信用 (chain crediting)**：一个轮次得分为 1 当且仅当其自身及所有上游答案依赖祖先的回答均正确。公式：
      $$ \text{AnsDepAcc} = \frac{1}{|\mathcal{T}_{\text{ans}}|} \sum_{t \in \mathcal{T}_{\text{ans}}} \text{corr}(t) \prod_{a \in \text{Anc}_{\text{ans}}(t)} \text{corr}(a) $$
    - **Overall**：上述三个指标的算术平均值。

## 实验与结果
- **数据集规模**：326 个视频，总时长最长 23.47 小时，覆盖 31 个语义领域、4 大类（生活娱乐、知识教育、艺术文学、体育竞技）。共 2476 个 QA 轮次，其中独立轮次 1089 个（43.98%），依赖轮次 1387 个（56.02%）。依赖边共 1794 条（情节依赖 1200 条，答案依赖 594 条），多父节点轮次 348 个。
- **评测模型**：25 个 MLLM（8 个闭源：Claude Opus 5, Sonnet 5, GPT-5.6-sol, GPT-5.5, GPT-5.4, Gemini 3.8 Flash, 3.5 Flash, 3.1 Pro Preview；17 个开源：Kimi K3, Qwen3.5/Qwen3-VL 系列, Keye-VL-1.5-8B）。
- **主要结果**：
    - **最强模型**：**Claude Opus 5** 整体得分 **45.7%**（TurnAcc 52.3%, EpiDepAcc 49.1%, AnsDepAcc 35.7%）。
    - **人类基准**：86.1%，差距显著。
    - **闭源模型**：Gemini 3.8 Flash (42.4%) 和 GPT-5.6-sol (41.7%) 紧随其后。AnsDepAcc 比 TurnAcc 低 16.6–22.9 个百分点，凸显链式错误的累积效应。
    - **开源模型**：**Kimi K3** 以 42.2% 的整体得分位列第三，接近顶尖闭源模型。其余 Qwen 系列模型得分在 16.2%–34.4% 之间，随参数规模增大而提升。
- **关键分析**：
    - **依赖距离**：准确率随依赖距离增加而下降（距离 1 为 30.2%，≥5 降至 23.1%）。
    - **父节点数量**：准确率随父节点增多而下降（Kimi K3 从 40.8% (1 个父节点) 降至 29.8% (3 个父节点)）。
    - **对话位置**：随着对话推进，依赖轮次的准确率持续下降，独立轮次下降较缓。
    - **答案历史影响**：用真实答案替换模型历史回答（oracle history）后，AnsDepAcc 大幅提升（如 Qwen3-VL-8B 从 12.3% 升至 32.4%），但仍未达到独立轮次水平，说明**仅纠正历史不足以保证当前轮次正确**。
    - **帧数消融**：增加采样帧数（16→64→128）普遍提升性能，但收益因模型而异。

## 相关工作脉络
1.  **与 MVBench, Video-MME, LongVideoBench 等视频理解基准的区别**：这些基准评估单轮、独立的问题，不构建对话历史，无法测量跨轮次记忆。VideoMemBench 通过显式依赖图填补了这一空白。
2.  **与 LoCoMo, LongMemEval, MemBench 等 LLM 记忆基准的区别**：这些工作专注于纯文本对话中的长期记忆，未涉及**视觉 grounded 的上下文记忆**，也未区分情节记忆与答案一致性记忆。
3.  **与 MMDU, MMRC 等多模态对话基准的区别**：MMDU 使用多张图片而非连续视频，MMRC 侧重通用多模态对话，均未针对**单视频长对话中的结构化跨轮次依赖**进行评测。
4.  **与 MT-Video-Bench 的区别**：后者虽然是多轮视频对话基准，但缺乏** typed dependency graph** 和**多父节点/长距离依赖**的设计，其问题结构不如 VideoMemBench 能精细刻画记忆类型。
5.  **定位差异**：本文不仅是评测，更通过严谨的必要性/非泄漏性验证 pipeline，确保了依赖关系的**真实性**和**结构性**，为研究“模型如何记住视频中看到和说过什么”提供了诊断性工具。

## 局限性与未来方向
- **数据集规模**：326 个视频、2476 轮次相对于大规模基准仍较小，未来可扩展至更多视频和更长的对话。
- **视频来源**：主要来自公开基准和网络，视频类型（如教程、体育、电影解说）和场景可能有限，未来可纳入更多样化的真实用户交互数据。
- **依赖构建成本**：依赖当前 LLM 生成和人工审查，规模化生产新数据仍需优化效率。
- **模型输入**：固定 128 帧采样，未探索更高效的动态帧选择或关键帧记忆机制。
- **未来方向**：可扩展至评估更长对话（>21 轮）、更复杂的因果推理链记忆、以及探究模型内部表征如何支持此类记忆，并指导模型架构或训练策略的改进。

## 研究启发与可借鉴点
1.  **依赖类型化设计思想**：将记忆需求明确区分为“情节记忆”（对视觉环境的回忆）和“答案记忆”（对自身输出的连贯性维护），这一分类清晰且对诊断模型弱点极具价值，可迁移至文本多轮对话或机器人导航等需要保持上下文一致性的任务评测中。
2.  **必要性-非泄漏性联合验证框架**：通过“移除父节点后 LLM 是否仍能答对”来检验必要性，通过“检查当前问题是否重述父节点信息”来检验非泄漏性，这种双重重构验证策略可靠且可自动化，可为构建其他需要保证问题间逻辑关联的数据集提供范式。
3.  **链式信用评估指标 (Chain Crediting)**：AnsDepAcc 指标不仅看当前轮次对错，还惩罚了上游答案依赖链上的任何错误，这能更真实地反映模型在长程推理中的**误差累积**问题，可借鉴到任何需要多步依赖推理的序列决策评测中。
4.  **实验设计洞察**：通过对比 self-rollout 与 oracle history 的结果，清晰地分离了“当前轮次理解错误”和“上游历史错误传播”两种失败模式，这种解耦分析对定位模型改进方向非常有用。
5.  **人机差距量化**：明确报告人类基准得分（86.1%），为评估模型性能的充分性提供了直观参照，避免了仅用模型间相对排名判断进展的片面性。

## 关键术语表
- **In-context video memory**：模型在处理单视频长对话时，检索和复用对话早期已确立的视觉信息与自身先前回答的能力。
- **Episodic Dependency**：一种跨轮次依赖，当前问题依赖于更早轮次所描述的特定视觉情节（场景、实体、事件），要求模型回忆“所见”。
- **Answer Dependency**：一种跨轮次依赖，当前问题建立在模型自身更早轮次的回答之上，要求模型保持回答的一致性，不重复判断视频。
- **Dependency Necessity**：依赖的有效性约束之一，指移除父节点后，当前问题必须无法仅凭视频和剩余对话历史作答。
- **Dependency Non-leakage**：依赖的有效性约束之一，指当前问题不得部分或全部重述父节点所建立的剧情描述或答案内容。
- **Chain Crediting**：评估答案依赖轮次准确率的计分规则，要求当前轮次及其所有上游答案依赖祖先的回答均正确才算本轮正确。
- **Self-rollout**：评估协议，模型按顺序回答问题，并使用自身生成的先前回答作为后续轮次的输入历史。
- **Oracle History**：评估对照，用问题的真实答案替换模型在对话历史中的先前回答，以隔离上游错误的影响。

## 可复现要素
- **数据集**：VideoMemBench，已在 HuggingFace 公开 (`https://huggingface.co/datasets/VideoMemBench/data`)。
- **代码**：项目代码在 GitHub 公开 (`https://github.com/Oliiveralien/VideoMemBench`)。
- **模型**：评测了 25 个闭源与开源 MLLM。
- **关键超参**：所有模型输入固定为 **128 帧**（带时间戳）；评估使用 GPT-5.4 mini 作为 judge；框架 prompt 详见附录 C。
- **视频来源**：Video-MME, VSI-Bench, Video-MMMU, LongVideoBench, EgoLife 及 YouTube 网络视频。
- **人类专家**：8 位专家参与数据集审查。
