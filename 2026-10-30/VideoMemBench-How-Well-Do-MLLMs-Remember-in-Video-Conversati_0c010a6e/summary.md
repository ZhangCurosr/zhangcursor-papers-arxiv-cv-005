# 论文速读：VideoMemBench: How Well Do MLLMs Remember in Video Conversations?

## 一句话总结
本文提出了 **VideoMemBench**，一个专门用于评估多模态大语言模型（MLLM）在视频对话中“上下文视频记忆”能力的基准测试。通过构建具有显式跨轮依赖关系的多轮对话，研究发现当前最先进的模型（如 Claude Opus 5）在此任务上的总体得分仅约为 45.7%，表明模型在长程视频对话中保持和利用历史信息方面仍存在显著不足。

## 研究问题与动机
1.  **现有基准的局限性**：现有的视频问答（QA）基准（如 MVBench, Video-MME, LongVideoBench 等）通常将评估分解为相互独立的问题，每个问题都可以仅凭视频和当前问题回答，无法衡量模型在连续对话中检索和复用早期建立信息的能力。
2.  **缺乏对“跨轮记忆”的结构化评估**：尽管一些多轮对话基准（如 MMDU, MT-Video-Bench）存在，但它们缺乏显式的、类型化的跨轮依赖图，无法区分和精确评估模型对“所见内容”（视觉片段）和“所言内容”（自身先前回答）的记忆能力。
3.  **核心问题界定不清**：在长视频多轮对话场景下，“上下文视频记忆”（in-context video memory）——即模型如何检索和重用对话中已建立的信息——这一关键能力未被系统地研究和量化。
4.  **验证标准缺失**：构建真正需要记忆的对话样本面临挑战，需确保依赖的必要性（无父轮则问题不可答）和非泄漏性（问题不直接陈述父轮信息），现有方法缺乏系统性的构建和验证流程。

## 核心贡献（创新点）
1.  **提出 VideoMemBench 基准**：构建了包含 326 个视频、2,476 轮对话的数据集，其中每轮对话都带有结构化的依赖图，明确标注了 Episodic（ episodic ）和 Answer（答案）两种类型的跨轮依赖，首次系统化评估 MLLM 的上下文视频记忆能力。（与已有工作区别：之前的基准要么单轮独立，要么多轮但无结构化依赖跟踪。）
2.  **设计双类型依赖机制**：引入了两种明确的依赖类型：Episodic Dependency（要求回忆模型先前看到的视觉片段）和 Answer Dependency（要求基于模型自身先前的回答进行推理），分别对应“记住所见”和“记住所言”。（与已有工作区别：传统多轮对话评估不区分记忆对象是视觉上下文还是语言输出历史。）
3.  **开发三层 LLM 构建与验证管线**：设计了包含规划器（planner）、生成器（generator）和裁判（judger）三个 LLM 角色的自动化构建流程，强制验证依赖的必要性（necessity）、非泄漏性（non-leakage）和视觉接地性（visual grounding），并结合人类专家审核确保数据质量。（与已有工作区别：提供了可复现的、多约束的自动化数据集构建方法。）
4.  **全面评测 25 个主流 MLLM**：在 VideoMemBench 上对 8 个闭源和 17 个开源 MLLM 进行了系统评估，揭示了当前 SOTA 模型在此任务上表现有限（最高分 45.7%），并深入分析了依赖距离、父节点数量、对话位置等因素对性能的影响。（与已有工作区别：提供了针对记忆能力的细粒度基准测试结果和分析。）

## 方法详解
**1. 依赖设计：**
-   **Episodic Dependency (EpiDep)**：当前问题依赖于对较早轮次中描述的视觉片段的回忆。例如，T1 描述了某个场景，T2 问“T1 提到的场景里有哪些角色？”，模型必须回忆 T1 对应的视觉内容才能回答。评估时不考虑父轮答案的正确性。
-   **Answer Dependency (AnsDep)**：当前问题依赖于模型自身在前面的轮次中给出的正确答案。例如，T1 确定了某个实体 X，T3 问“X 接下来做了什么？”，模型必须记住 T1 的答案 X 是什么才能回答 T3。评估采用链式信用（chain crediting），只有当当前轮及其所有 AnsDep 祖先轮都答对时才计分。

**2. 构建要求：**
-   **Req-1: 依赖必要性 (Necessity)**：移除父轮后，即使有视频和其余对话，该问题也应无法回答。
-   **Req-2: 非泄漏性 (Non-leakage)**：问题不能部分或全部重述父轮建立的场景描述或答案。
-   **Req-3: 视觉接地 (Visual Grounding)**：每轮（无论是否依赖）的答案都必须能在视频中看到可验证的视觉事实支持。

**3. 构建管线 (Pipeline)：**
-   **视频收集**：从现有基准（Video-MME, VSI-Bench 等）和网络（YouTube 体育、教程等）收集约 3.2k 视频，按四个大类（生活娱乐、知识教育、艺术文学、体育运动）和 31 个子类别组织。
-   **依赖规划 (Planner)**：LLM 作为规划器，生成全局对话计划，包括视频摘要、对话指南、依赖图（节点为轮次，边为 Episodic/Answer 类型）和每轮意图。依赖图必须在生成问题前确定。
-   **轮次生成 (Generator)**：LLM 作为生成器，按计划逐轮生成。对于依赖轮，使用指代表达（如“T1 中提到的场景”）而非重述信息。答案必须基于证据窗口的视觉帧。
-   **轮次检查 (Judger)**：LLM 作为裁判，逐一验证每轮是否满足必要性、非泄漏性和视觉接地性。失败则反馈给生成器重新生成，连续两次失败触发局部重新规划。
-   **专家审核 (Human Review)**：8 名专家对所有通过自动检查的对话进行最终审核，修正答案错误、无效依赖或信息泄漏。

**4. 评估协议：**
-   所有模型使用相同的固定 128 帧（带时间戳）输入。
-   采用 **self-rollout** 协议：模型回答每一轮后，其回答被保留在历史中，作为后续轮次的输入的一部分。输入格式为：$V \parallel (q_1, \hat{a}_1) \parallel ... \parallel (q_{t-1}, \hat{a}_{t-1}) \parallel q_t$。
-   评估指标：
    -   **TurnAcc**：所有轮次的整体准确率，每轮独立评分。
    -   **EpiDepAcc**：仅评估具有 Episodic 依赖的轮次准确率，独立评分。
    -   **AnsDepAcc**：评估具有 Answer 依赖的轮次，采用链式信用（公式见原文），反映从早期错误中累积的难度。
    -   **Overall**：上述三个指标的平均值，用于综合排名。

## 实验与结果
-   **数据集**：326 个视频，2,476 轮对话，其中 1,387 轮（56%）为依赖轮（含 1,794 个依赖边：1,200 个 Episodic，594 个 Answer）。视频最长可达 23.47 小时，平均 7.6 轮/对话。依赖距离可达 9 轮，最多 3 个父节点。
-   **评估基线**：25 个 MLLM（8 闭源：Claude Opus 5, Gemini 3.8 Flash, GPT-5.6-sol 等；17 开源：Kimi K3, Qwen3.5/Qwen3-VL 系列等）。人类基准得分 86.1% (Overall)。
-   **主要结果**：
    -   **最强模型**：**Claude Opus 5** 以 **45.7%** 的 Overall 得分领先。
    -   **具体表现**：Claude Opus 5 的 TurnAcc=52.3%, EpiDepAcc=49.1%, AnsDepAcc=35.7%。AnsDepAcc 显著低于 TurnAcc 和 EpiDepAcc（差距约 10-17 个百分点）。
    -   **闭源模型对比**：GPT-5.4 (36.3%)、Gemini 3.1 Pro Preview (39.1%) 等表现较低。AnsDepAcc 普遍比 TurnAcc 低 16.6-22.9 个百分点。
    -   **开源模型对比**：Kimi K3 表现最佳（Overall 42.2%, TurnAcc 50.5%），接近顶尖闭源模型。Qwen3.5 系列随参数增大性能提升（0.8B: 16.2% -> 27B: 34.3%）。
    -   **分析发现**：
        1.  **依赖距离**：平均准确率随依赖距离增加而下降（距离 1: 30.2% -> 距离>=5: 23.1%）。
        2.  **父节点数量**：准确率随父节点数增加而稳定下降（1 个父节点: 40.8% -> 3 个: 29.8% for Kimi K3）。
        3.  **对话位置**：后期轮次（>=turn 5）的依赖轮准确率下降更明显。
        4.  **历史影响**：使用 oracle 历史（替换为真实答案）能使 AnsDepAcc 大幅提升（如 Qwen3-VL-8B 从 12.3% 升至 32.4%），但仍低于独立轮准确率，表明错误历史是主要困难来源，但仅有正确历史仍不足。
        5.  **帧数消融**：增加采样帧数（16->128）普遍提升性能，但各模型增益不同。

## 相关工作脉络
1.  **视频理解基准**：MVBench, Video-MME, LongVideoBench 等侧重于单轮或多轮但问题独立的视频理解能力评估，缺乏对跨轮记忆的结构化测量。（VideoMemBench 与之对比：引入显式依赖图和 typed edges。）
2.  **多轮对话基准**：MMDU（多图像）、MT-Video-Bench（视频多轮，但无依赖图）评估对话质量，但不区分记忆类型或验证依赖必要性。（VideoMemBench 与之对比：聚焦单视频内跨轮记忆，提供 typed dependency graph。）
3.  **文本记忆基准**：LoCoMo, MemBench, LongMemEval 等评估 LLM 的长期对话记忆，但未涉及视觉模态下的记忆挑战。（VideoMemBench 与之对比：将记忆评估扩展到多模态视频领域。）
4.  **长上下文能力**：RULER, Babilong 等测试 LLM 的长上下文处理能力，但未结合多轮对话中的动态记忆需求。（VideoMemBench 与之对比：关注对话过程中信息的检索与复用，而非静态长文本处理。）
5.  **视频 QA 与推理**：EgoSchema, Video-MMMU 等评估视频内容理解和推理，但问题间无关联。（VideoMemBench 与之对比：构建相互关联的问题链，模拟真实对话场景。）

## 局限性与未来方向
-   **数据集规模**：当前 326 个视频、2476 轮对话规模相对有限，可能不足以覆盖所有类型的记忆挑战和视频域。
-   **依赖复杂度**：虽然引入了多父节点和长距离依赖，但依赖图的复杂性和多样性仍有提升空间（如循环依赖、并行分支等）。
-   **模型评估**：主要评估了现有 MLLM 的零样本/少样本能力，未针对此任务进行专项微调或训练探索。
-   **未来方向**：可扩展数据规模和依赖类型；研究模型架构和训练策略以增强上下文视频记忆；探索更高效的信息检索和存储机制；与 Agent 系统中的长期记忆模块结合。

## 研究启发与可借鉴点
1.  **依赖驱动的数据构建范式**：三层 LLM 角色（规划、生成、裁判）结合人类审核的自动化构建流程，保证了数据的质量和内容的有效性，此方法可迁移至其他需要复杂上下文关系的任务基准构建（如代码生成、长文档问答）。
2.  **细粒度的记忆评估指标**：区分“记住所见”（EpiDepAcc）和“记住所言”（AnsDepAcc）并提供链式信用评分，为评估模型的“状态管理”能力提供了精细工具，可启发其他领域（如多轮对话、Agent）的记忆评测设计。
3.  **必要性/非泄漏性验证逻辑**：通过移除父轮和检查信息重述来验证依赖的必要性，这种自动化验证方法可用于确保任何依赖型数据集的真实质量，防止“虚假依赖”。
4.  **Self-rollout 评估协议**：使用模型自身历史回答作为后续输入的评估设置，更贴近实际应用中的对话场景，揭示了错误累积效应，此协议可推广至任何多轮交互系统的评估。
5.  **分析维度借鉴**：从依赖距离、父节点数量、对话位置等多个维度分析性能衰减，为诊断模型记忆短板提供了系统框架，可供类似研究参考。

## 关键术语表
**In-context video memory**：指 MLLM 在连续的视频多轮对话中，检索和重用对话早期已建立的视觉或语言信息的能力。
**Episodic Dependency**：一种跨轮依赖类型，指当前问题依赖于对较早轮次中描述的特定视觉片段（场景、实体等）的回忆。
**Answer Dependency**：一种跨轮依赖类型，指当前问题依赖于模型自身在较早轮次中给出的正确答案，用于后续的推理或追问。
**Chain crediting**：用于评估 Answer 依赖轮次的方法，只有当前轮及其所有 Answer 依赖祖先轮的回答都正确时，才计为正确。
**Dependency Necessity**：验证依赖有效性的核心要求，指移除指定父轮后，问题应无法仅凭视频和剩余对话被回答。
**Dependency Non-leakage**：验证依赖有效性的核心要求，指问题本身不应部分或全部重述父轮已建立的信息，以免削弱依赖的必要性。
**Visual Grounding**：要求每个问题的答案都能在视频中找到对应的、可验证的视觉证据支持。
**Self-rollout**：评估协议，模型在每一轮的输入中包含其自身之前轮次的实际回答，模拟真实的连续对话交互。
